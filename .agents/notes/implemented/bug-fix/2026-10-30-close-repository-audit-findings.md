# Agent Note: 关闭仓库审查中的保存、引用状态与诊断缺口

Status: implemented

## Problem

2026-10-30 的仓库审查确认六类问题：站位保存获取了新版本却提交旧草稿，离开保护未检查
站位草稿；参考图过期没有沿父图传播且来源缺失被跳过；节拍匹配跨场次并用短相同片段冒充
承载证明；跨镜对白全算到第一镜；Dashboard 未消费完整结构检查和资产诊断。

背景决定见
[真实图片异步任务、项目参考图版本与可编辑站位](../../implemented/architecture/2026-10-30-real-provider-staging-and-release-candidate.md)。

## Decision

- `structural_invariant`：草稿绑定开始编辑时的 Markdown 字节版本；保存冲突保留草稿，
  原文和站位共用离开保护，保存期间的再次编辑也不能丢失。
- `structural_invariant`：参考图状态按精确来源路径、当前输出字节和父图依赖图计算；
  来源缺失、父图失效和循环均显式报告，不依赖视图排序。
- `structural_invariant`：逐块承载只采用同场完整原文的明确声明，部分相似片段只作核对提示；
  不再以连续四个相同字符证明动作完成。保留 Markdown 唯一内容源，不新增节拍文件。
- `structural_invariant`：已接受项目语速的估时按承载区间核算容量，不任意把跨镜对白归给第一镜；
  未知镜长保持未知，结果不代替剪辑入出点或创作质量判断。
- `structural_invariant`：Dashboard 在已经安全读取的同一文档快照上消费检查器结果，
  安全读取项目语速；检查失败与非阻断提示分开展示，沿用原有文件访问约束。
- 跨镜对白用确定性的容量图核对是否存在可容纳分配，不推断实际入出点；可行容量不是表演质量 verdict。
- 原文编辑器按 textarea 实际使用的 LF 文本计算定位与脏状态，文件版本仍绑定原始字节，兼容 CRLF。
- 来源目标映射列出三个包含改写的技能与仓库迁移器，各独立技能随包携带许可与 NOTICE。
  精确版本随包内容和伴随依赖更新，使用固定中央控制脚本和 ClawHub 0.23.3 SDK 离线核对文件清单；
  不把未执行的外部发布或人工验收写成通过。

## Alternatives considered

- **保存前重新取版本再比较**：能缩短提交时的竞争窗口，但会给旧草稿套上新授权，
  不能证明编辑基线，故采用开始编辑时的版本。
- **保留模糊相似度降低旧样例迁移量**：能兼容很多转述，但反向动作也能过门；
  只保留诊断用途，示例与迁移器填写真实承载段落的完整来源。
- **让 Dashboard 直接按项目路径重读检查器输入**：复用 CLI 最少代码，但绕开固定目录读取，
  还会混合不同快照；选择传入已读取文本与语速。

## Consequences

保存与状态更可信，新增检查能被创作者看见。代价是部分旧来源短引文需要补完整原文，
测试覆盖真实前端调用链、保存期间修改、依赖多层传播与模糊匹配反例；严格文本声明仍不能替代语义审查。
浏览器回归补入冲突恢复、离开保护、诊断显示与页面异常收集；截图和依赖工具保留在仓库外。
