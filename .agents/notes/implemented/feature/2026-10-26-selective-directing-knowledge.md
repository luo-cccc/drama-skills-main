# Agent Note: 按任务消费打戏、画风与面部表演知识

Status: implemented

## Problem

本地用户要求从公开的漫剧老李 V7.4.26 吸收导演知识。当前 drama v0.9.2 已有接触动作、画风继承和模型限定的反应镜经验；整体复制会重复并引入互斥配方，仅放置参考文件又不能证明它参与决策。

相关既有决定：规则四级分级与脚本边界、每个技能自包含、反应镜默认按模型限定，以及当前五文档写作入口。实施保留这些决定。

## Decision

按负责人接入三个专题：分镜的打戏编排，视频的打戏实现和面部表演。画风增强已有 Look Development 与本地阶段参考。入口明确适用条件，决策前读取，产物使用现有格式，完成时核对具体决定；总控索引不成为子技能的必读依赖。

首批建议作为 craft_default 或 taste_option；不引入统一动作数、镜长、百分比或肌肉表格。既有剧情、状态与模型方言保持权威。来源许可随改编的独立技能携带。

评估分别记录读取证据、落实与继承、离线编译、真实结果、误触发和成本。新增任务语料与人工核对标准，结构可达检查不冒充模型行为证据。

## Alternatives considered

- 复制全套总控和引擎：细节全面，但破坏现有职责、增加上下文负担且带入冲突规则。
- 只增加参考资料：改动小，但工作流没有决策前入口和完成核对，可能完全不被采用。
- 用关键词或固定动作配额阻断：容易自动化，但无法证明语义、剧情保真或真实生成质量。

## Consequences

可按主题独立回退；现有项目只在请求范围内采用新知识。模型行为与媒体效果需要后续独立任务和真实生成验证，未取得证据不得声称已提升。原版快照、应用清单与部署文件摘要保留在仓库外。

实施记录：已接入三个专题、现有画风资料、技能触发和完成核对；新增中性开发案例。静态封装与链接检查通过。一次独立文本试跑记录了相应专题的读取和产物采用，尚未验证真实媒体或稳定增益。当前环境拒绝启动 Python/Ruff，完整单测、官方 quick_validate 与 Ruff 本轮未运行；旧版测试结果不作为本次通过证明。
