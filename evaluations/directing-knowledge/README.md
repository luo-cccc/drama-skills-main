# 导演知识的文本消费验收

这组案例用于独立运行，不是新的创作模板。`cases.json` 是公开的合成开发案例，预期行为只供评审使用，
执行者只接收当前 case 的 request 和选择的技能副本。生成结果、实际读取证据和 A/B 标签存放在仓库外，
不进五份创作文档，也不随独立技能安装。

## 执行

固定原版和候选版的文件摘要、模型与设置，分别在隔离上下文运行同一 request。输出到分开的目录，
只给技能与原始输入，不提供本页评审标准、另一个版本的作品或来源知识库。模型执行器有读取日志时
保留真实文件路径、有效行段和先后；没有日志就把读取证据标未知，不以模型自报代替。

相同模型、设置、输入和可用资源下比较。案例已用于调规则后留在开发集，泛化结论使用新的未见案例。
真实图片、视频、费用与媒体兑现需另外试跑，本语料默认只授权文字产物。

## 消费与质量分开记录

每次运行按下面的问题记录实际证据，不要求模型把这些字段写进创作产物：

- 适用哪个主题，是否取得有效章节、是否在决策前取得；
- 哪个具体产物决定体现了知识；下游是否继承、有没有改写上游事实；
- 不采用或不加载是否符合当前景别、任务阶段、素材和模型；
- 格式、引用、声音、起终状态是否仍与现有流程相容；
- 读取回合、文本量、人工修订和新增生成需求；无媒体时兑现状态为未测。

收到更长或术语更多的稿件不直接加分。评审先隐去版本标签，比较保真、可读性、连续性、执行负担与
任务范围。原版已满足的部分记作持平；改造的收益要能指出新增决定，而不是给原版能力重新命名。

## 评审条目

| 案例 | 核对重点 | 不接受的副作用 |
|---|---|---|
| C01 | 脱握、受力、落点与持物连续，SHOT 到 MOTION 的交接 | 添加伤势、反击或无来源效果 |
| C02 | 幻想效果有作用对象、尺度参照与结果 | 新能力或无来源死亡／湮灭 |
| C03 | 无“打戏”关键词仍识别当前接触编排 | 只凭词面触发 |
| C04 | 只写剧本，表演与剧情在请求范围内 | 自动分镜、镜头表与投产 |
| S01 | 身份、地点、压力帧共享可观察风格 | 仅用风格名或替换人物地理 |
| S02 | 已接受方向允许夜景例外 | 强拉同亮度或重新要求全套选择 |
| S03 | 新方向与旧参考冲突定位准确 | 宣称文字已改变图片或直接生成 |
| E01 | H3 近景反应有来源、可见性与正确发声 | 复刻全脸字段或擅自升级情绪 |
| E02 | Seedance 2.5 保留适用模型依据 | 套 H3 数量／秒点配方 |
| E03 | 背影远景使用可见通道 | 提示不可见眼部动作或擅改近景 |
| X01 | 同镜动作与对白相容，主职责明确 | 闭嘴说话、为了消费而堆技巧 |
| X02 | 只修一镜，保持其他事实和稳定 ID | 整集重写或建立平行状态文件 |

局部改动可先运行命中主题与相邻反向案例。只有文档可达检查时记录为“接线已验证”；有真实执行作品
才能记录文本落实。有生成媒体与准确输入证据后，才讨论兑现率和合格镜头成本。
